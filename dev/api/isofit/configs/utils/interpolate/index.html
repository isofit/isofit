    source package isofit.configs.utils.interpolate

    Configuration interpolation utilities for variable substitution.

    This package loads configuration files with inheritance, override, and variable interpolation support. It allows using ${key} or ${.key} syntax to reference other values within the configuration, and supports command-line overrides through Click contexts.

    Configs are plain nested dict / list trees throughout.

    The pipeline, run in order by :func:load, is split into one module per stage:

    • :mod:.common -- :func:read plus the dict helpers :func:get_dotted, :func:locate, :func:set_dotted, and :func:merge
    • :mod:.inherit -- ^^ inheritance (:func:patch, :func:resolve_file)
    • :mod:.overrides -- dotted-key overrides (:func:parse_overrides, :func:override)
    • :mod:.resolve -- ${...} interpolation (:func:interp, :func:interpolate)
    • :mod:.load -- :func:load, which chains the stages above
    • :mod:.cli -- the isofit config command group

    source get_dotted(data: Union[dict, list], key: str) → Any

    Look up a value in a nested dict/list tree by dotted key.

    Mapping keys are separated by . and list items are indexed with [i], so "a.b[1].c" is data["a"]["b"][1]["c"]. Negative indices count from the end.

    A literal key always wins over descending, and each separator is tried as a split point from left to right. This lets a key that itself contains dots be addressed: with {"env": {"srtmnet": "/p", "srtmnet.file": "f.h5"}}, "env.srtmnet.file" resolves to "f.h5".

    Parameters

    • data : dict or list — The tree to search.

    • key : str — Dotted key, e.g. "forward_model.instrument.SNR" or "implementation.inversion.windows[0]". An empty key returns data itself.

    Returns

    • Any — The value at key.

    Raises

    • KeyError — If key does not resolve to a value, including when it indexes past the end of a list or descends into a scalar.

    Examples 

    data = {"a": {"b": [{"c": 1}, {"c": 2}]}}
get_dotted(data, "a.b[1].c")

    2

    get_dotted(data, "a.b[-1]")

    {'c': 2}

    source locate(data: Union[dict, list], key: str) → list[tuple[Union[dict, list], Any]]

    Find where a dotted key lives in a nested dict/list tree.

    Resolves key exactly as :func:get_dotted does, but returns the path taken rather than the value, so callers can tell which section a value belongs to and update it in place.

    Parameters

    • data : dict or list — The tree to search.

    • key : str — Dotted key, e.g. "a.b[1].c".

    Returns

    • list of (dict or list, str or int) — Each (container, slot) step from data down to the value, which is path[-1][0][path[-1][1]]. List indices are normalised to be non-negative. An empty key returns an empty path.

    Raises

    • KeyError — If key does not resolve to a value.

    Examples 

    data = {"a": {"b": [{"c": 1}, {"c": 2}]}}
[slot for _, slot in locate(data, "a.b[-1].c")]

    ['a', 'b', 1, 'c']

    source merge(dst: dict, src: dict) → dict

    Deep-merge src into dst in place; src wins on conflict.

    Nested mappings are merged key by key. Every other value, including lists and an explicit None, replaces the value in dst outright. Values taken from src are deep-copied, so later mutation of dst never reaches back into src.

    Parameters

    • dst : dict — The mapping to update.

    • src : dict — The mapping to merge on top.

    Returns

    • dict — The same dst, updated.

    source read(config: Union[str, Path]) → dict

    Load a config file into a dict, dispatching on its extension.

    Both YAML (.yml / .yaml) and JSON (.json) are supported. An empty file loads as an empty dict.

    Parameters

    • config : str or pathlib.Path — File path to the config to read.

    Returns

    • dict — The loaded configuration.

    Raises

    • ValueError — If the file's extension is not a supported config format, or the file's top level is not a mapping.

    source set_dotted(data: Union[dict, list], key: str, value: Any) → None

    Set a value in a nested dict/list tree by dotted key, in place.

    Uses the same key resolution as :func:get_dotted, including [i] list indexing. Missing or null intermediate sections are created as empty dicts. Lists are never created or extended, so an indexed item must already exist.

    A mapping assigned onto an existing mapping is deep-merged into it (see :func:merge), so other keys of that section are kept. Any other value, including lists and None, replaces the existing one outright. The value is deep-copied, so data never aliases it.

    Parameters

    • data : dict or list — The tree to update.

    • key : str — Dotted key, e.g. "forward_model.instrument.SNR" or "implementation.inversion.windows[0]".

    • value : Any — Value to assign.

    Raises

    • KeyError — If a list index in key is malformed or out of range.

    • TypeError — If an intermediate section of key is not the container the key expects: a mapping before ., a list before [i].

    Examples 

    data = {"a": {"b": [1, 2], "c": {"x": 1}}, "n": None}
set_dotted(data, "a.b[-1]", 3)
set_dotted(data, "a.c", {"y": 2})
set_dotted(data, "n.k", 4)
data

    {'a': {'b': [1, 3], 'c': {'x': 1, 'y': 2}}, 'n': {'k': 4}}

    source patch(box: dict, full: dict, _seen: Optional[set] = None, base_dir: Optional[Path] = None, cache: Optional[dict] = None, file: Optional[Path] = None) → dict

    Merge one or more referenced sections into box in place.

    Consumes the ^^ key from box, whose value names either a single section (str) or several sections (list). Each name is treated as an inherited default; they are applied lowest-priority first, in the order listed, and box's own keys always win on conflict. Referenced sections are resolved recursively, so a section that itself declares ^^ has its own ancestors folded in first.

    For example A: {^^: [B, C]} with B: {^^: D} yields the precedence D < B < C < A (A's own keys highest, D lowest).

    References may point either at a section in the same file (^^: default) or at a section in another file using file:section syntax (^^: bases/default.yml:srtmnet). The referenced file may be YAML or JSON. The file portion is resolved relative to base_dir (the directory of the file being loaded); a bare file with no :section inherits that file's top-level mapping.

    Parameters

    • box : dict — The config subsection to patch; mutated in place. Its ^^ key is removed.

    • full : dict — The full config used to resolve same-file section names.

    • _seen : set, optional — Internal set of (file, section) keys currently being resolved on this recursion chain, used to detect circular ^^ references. Should not be passed by callers.

    • base_dir : pathlib.Path, optional — Directory used to resolve the file portion of cross-file references. Defaults to the current working directory.

    • cache : dict, optional — Internal mapping of resolved file path to its loaded config, so each referenced file is read from disk only once per patch tree.

    • file : pathlib.Path, optional — Resolved path of the file full was read from. Same-file references are identified by it for cycle detection, so sections that share a name across files are not mistaken for one another. Defaults to None, which treats full as an anonymous in-memory config.

    Returns

    • dict — The same box, updated with the merged sections.

    Raises

    • ValueError

    • KeyError

    source resolve_file(sect: str, base_dir: Path, cache: dict) → tuple

    Resolve a cross-file ^^ reference of the form path[:section].

    The path is taken relative to base_dir (the directory of the file that declared the reference) and loaded at most once per patch tree via cache. With no :section suffix the referenced file's top-level mapping is inherited; otherwise the named section within it is used.

    The split is made on the colon that immediately follows a supported file extension (.yml / .yaml / .json), so colons elsewhere in the path are left untouched.

    Parameters

    • sect : str — The raw reference string, e.g. bases/default.yml:srtmnet or ../common.json.

    • base_dir : pathlib.Path — Directory used to resolve path relative references.

    • cache : dict — Mapping of resolved file path to loaded config, mutated in place.

    Returns

    • tuple — (ref_full, ref, ref_dir, ident) where ref_full is the referenced file's full config (for resolving that file's own same-file ^^ refs), ref is a copy of the selected subsection, ref_dir is the directory of the referenced file (base for its cross-file refs), and ident is a hashable (path, section) identity for cycle detection.

    Raises

    • FileNotFoundError

    • KeyError

    source load(config: str, section: Optional[str] = None, ctx: Optional[click.Context] = None, interp: bool = True) → dict

    Loads a config from a yaml or json file

    Parameters

    • config : str — File path to the config (.yml, .yaml, or .json)

    • section : str — Returns only this subsection of the config

    • ctx : click.Context or list of str or dict, default=None — Overrides, in any shape accepted by :func:~.overrides.parse_overrides

    • interp : bool, default=True — Calls interpolate on the config before returning

    Returns

    • config : dict — Loaded configuration

    Raises

    • KeyError — If section is not a top-level section of the file.

    source override(box: dict, ctx: Union[click.Context, list[str], dict, None]) → dict

    Patch the config in place with dotted key/value overrides.

    The overrides may be given in any shape accepted by :func:parse_overrides (click.Context, CLI arg list, or dict); normalization is delegated there, so this function only applies an already-canonical mapping. Keys are dotted (see :func:~.common.set_dotted), so "forward_model.instrument.SNR" resolves into nested sections, creating any that are missing.

    A mapping overriding an existing section is deep-merged into it, keeping the section's other keys; any other value, including lists and None, replaces the existing one outright.

    Parameters

    • box : dict — The loaded config to override; mutated in place.

    • ctx : click.Context or list of str or dict or None — The overrides, in any shape accepted by :func:parse_overrides.

    Returns

    • dict — The same box, updated with the overrides.

    source parse_overrides(source: Union[click.Context, list[str], dict, None]) → dict

    Normalize any override specification into a plain {dotted.key: value} dict.

    This is the single place that knows the different shapes overrides can arrive in, so the rest of the code only ever deals with a dict:

    • None -> {} (no overrides);
    • a click.Context -> its extra --dotted.key value args are parsed;
    • a list[str] of those same CLI tokens -> parsed directly;
    • a dict of dotted keys to already-typed values -> returned as-is.

    Only the CLI forms are literal-parsed; mapping values are used verbatim, so callers passing a dict provide real Python objects (SNR=500, not "500").

    Parameters

    • source : click.Context or list of str or dict or None — The override specification in any supported shape.

    Returns

    • dict — Mapping of dotted key (e.g. "forward_model.instrument.SNR") to value.

    source interp(val: str, rel: dict, full: dict, _seen: Optional[set] = None) → Any

    Interpolate ${...} references in a single string against the config.

    Format: ${.key} or ${key}. A leading dot makes the key relative to the subsection the original value lives in (rel); otherwise it resolves from the top of the config (full). After substitution the result is parsed as a Python literal when possible, so a fully-substituted string can become e.g. an int/list.

    Referenced values are resolved depth-first in their own context before being substituted: a referenced string has its relative refs resolved against its own section, and a referenced list or mapping is fully interpolated. Either way the resolved value is written back into the config, so each value is resolved once and the result does not depend on key order.

    Parameters

    • val : str — The value to interpolate.

    • rel : dict — The subsection used to resolve relative (${.key}) references.

    • full : dict — The full config used to resolve absolute (${key}) references.

    • _seen : set, optional — Internal set of the values currently being resolved on this recursion chain, used to detect circular references. Should not be passed by callers.

    Returns

    • Any — The interpolated value; a literal (int/list/...) when it parses as one, otherwise the substituted string (or val unchanged if it had no refs).

    Raises

    • ValueError

    • KeyError

    source interpolate(box: Union[dict, list], full: Optional[dict] = None, rel: Optional[dict] = None, _seen: Optional[set] = None) → Union[dict, list]

    Recursively interpolate every ${...} reference in a config tree in place.

    Walks box (a dict or list), replacing each string value via :func:interp. full is the full config used for absolute references; rel is the current subsection used for relative ones. Both default to box itself on the first call and are threaded down as the walk descends into subsections.

    :func:interp resolves each referenced value depth-first and writes it back, so the result is the same whatever order the keys are walked in.

    Parameters

    • box : dict or list — The config node to interpolate; mutated in place.

    • full : dict, optional — Full config for absolute references. Defaults to box on the first call.

    • rel : dict, optional — Subsection for relative references. Defaults to full.

    • _seen : set, optional — Internal set of the values currently being resolved, used by :func:interp to detect circular references. Should not be passed by callers.

    Returns

    • dict or list — The same box, with all ${...} references interpolated.
